# 05 · Security and identity

`OIDCIdentityService` verifies signed JWTs against configured issuer, audience, JWKS, expiry, issued-at and subject claims. Only explicitly configured RS256/ES256 algorithms are allowed. Use an organization's Entra/federated issuer as configured; Adobe Admin Console enrollment and Salesforce OAuth remain outside the kernel. A token alone grants no marketing roles. `IdentityStore` resolves the verified issuer/subject into an administrator-enrolled GenUI principal, permitted tenant, licenses and provider identities. Token role claims are ignored.

`PostgresIdentityStore.enroll` stores non-secret identity mappings and refuses reassigning an enrolled external identity to another tenant. Enrollment is privileged host code; no unauthenticated enrollment endpoint is supplied. Runtime provider identities must match the principal tenant. Gateway scopes, endpoint trust and provider-side OAuth permissions are all required; local permissions never elevate an underlying vendor token.

Human approvals are persisted per immutable plan stage, scoped to a tenant and issued by an independent `approver` principal. Approval does not override current capability permissions, licenses or provider prerequisites; these are checked again during execution. Rejection is terminal and emits an audit event. `operator` is required for uncertain-outcome reconciliation. Compensation needs explicit `workflow.compensate` permission.

The Studio API is a **single-user fixture development host**, with fixed requester/reviewer identities, bounded JSON request bodies, local-only API binding, origin checks and no credential-entry fields. OIDC verification is an integration package; it is not wired to a production login UI. Do not expose Studio as a multi-user service. Hosts must add authenticated sessions, CSRF/session protections, per-user context resolution, durable secret management/refresh, egress controls, data retention/encryption, quotas and operational monitoring.

Remote tool descriptions/content are untrusted. The planner uses only local capability metadata; remote descriptions cannot grant roles, change effects or remove approval gates. Output schemas validate normalized result data before state is stored. Connector implementations must strip unrelated/private fields. Rate limit buckets are local to one gateway process; enterprise quotas require a shared rate-limit service. SQL is parameterized and tenant-keyed. The adapter does not configure database RLS or admin-user separation for you.
